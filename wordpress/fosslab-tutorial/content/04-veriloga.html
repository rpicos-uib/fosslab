A behavioural model describes what the op-amp does with a few equations instead of eight transistors. It simulates much faster, and it is what you use when the op-amp is one block of a bigger system (a filter, an ADC). Here it will also let us run Monte Carlo without the transistors (chapter 10).

1. The model: another view of the op-amp

The model describes the same op-amp, with the same pins, so it is one more view of the cell opamp, next to its schematic, symbol and layout. In the Library Manager, right-click opamp > New view > Verilog-A. FOSSLab writes opamp.va with a module that has the symbol's pins, and opens it in the text editor:

module opamp(INP, INN, OUT, IBIAS, VDD, VSS);
    inout INP, INN, OUT, IBIAS, VDD, VSS;
    electrical INP, INN, OUT, IBIAS, VDD, VSS;
    electrical n1;                      // internal node: the dominant pole

    parameter real A0dB    = 57.6;      // DC gain (dB)
    parameter real GBW     = 16.2e6;    // gain-bandwidth product (Hz)
    parameter real VOS     = 1.98e-3;   // input-referred offset (V)
    parameter real SR      = 10.6e6;    // slew rate (V/s)
    ...
    analog begin
        a0   = pow(10, A0dB / 20);
        gm   = 1e-3;                    // any value: only gm*r1 and gm/c1 matter
        r1   = a0 / gm;                 // DC gain a0 = gm * r1
        c1   = gm / (2 * `M_PI * GBW);  // unity gain at GBW
        imax = SR * c1;                 // slewing: c1 charged at most with imax
        vmid = (V(VDD) + V(VSS)) / 2;

        // input stage: limited transconductance into r1 // c1
        I(n1, VSS) <+ -imax * tanh(gm * (V(INP, INN) + VOS) / imax);
        I(n1, VSS) <+ (V(n1) - vmid) / r1;
        I(n1, VSS) <+ c1 * ddt(V(n1, VSS));

        // output: follows n1, kept VMARGIN away from the rails
        ...
        I(OUT, VSS) <+ (V(OUT) - vt) / ROUT;
    end
endmodule

The whole file, with comments, is in the reference library (opamp_tut/opamp/opamp.va). One pole (r1 and c1), slew-rate limiting (the tanh), output limits and supply current: four numbers taken from the transistor-level simulation describe the op-amp.

2. Compile it

Right-click the view Verilog-A > Compile (OpenVAF). OpenVAF turns the model into a library that ngspice loads (opamp.osdi); the view Compiled model (OSDI) appears, greyed like the other results. If OpenVAF finds an error, the window shows the line. You need not recompile after every change: a simulation that uses the model compiles it again whenever the source is newer.

3. Simulate the model instead of the transistors

No new symbol and no new testbench: tb_opamp_ac already places the op-amp's symbol. What is simulated inside that symbol is chosen in the Simulation Environment, tab Views, one row per cell of the testbench that has more than one view:

  1. Select tb_opamp_ac and press Sim. Environment.
  2. Keep the transistor-level setup as it is: next to Setup, press Save as... and call the new setup model. A testbench can have several setups (the default one, model, ...): the list next to Setup switches between them, and each keeps its own variables, views, corners and results.
  3. Tab Views: double-click opamp_tut / opamp and choose Verilog-A model (opamp.va). The dialog lists the model's parameters with their defaults: leave them empty for now (chapter 10 fills them in).
  4. Tab Outputs: delete pdiss and g1m, which the model is not meant to reproduce. Tab Corners: delete the corners; they change the transistors' models, and this setup has no transistors.
  5. Run nominal.

The schematic is not touched. FOSSLab writes the testbench's netlist as usual and replaces the op-amp's subcircuit by one that holds the compiled model, connecting the pins by name; it is the same mechanism as post-layout simulation (chapter 7), where the view is the extracted netlist. From the command line: fosslab views opamp_tut tb_opamp_ac --setup model --set opamp=veriloga, then fosslab sim opamp_tut tb_opamp_ac --setup model.

One cell, many views, and the testbench decides which one to simulate: this is how large designs are verified. A system can be simulated with most blocks as fast models and one block at transistor level (or extracted), and the same idea will bring digital blocks (Verilog) into the analog testbenches.

4. Model versus transistors

Transistors (setup default)Verilog-A (setup model)
DC gain57.61 dB57.60 dB
Unity-gain frequency16.17 MHz16.20 MHz
Output offset1.73 mV1.71 mV
Phase margin60.4°89.5°

Gain, bandwidth and offset agree. The phase margin does not: a one-pole model always has 90°. The real op-amp has a second pole at its output (from M6's transconductance and the load) and the Miller zero. Keep this in mind: it is the subject of the exercise in chapter 11.

Why VOS = 1.98 mV when the measured offset is 1.73 mV? The testbench measures the follower's output error, v(out) − v(inp). For the model this is VOS minus the gain error of a finite-gain follower, (VCM − VDD/2)/A0 = (0.8 − 0.6)/759 = 0.26 mV. So VOS = 1.73 + 0.26 ≈ 1.98 mV reproduces the transistor-level number.
