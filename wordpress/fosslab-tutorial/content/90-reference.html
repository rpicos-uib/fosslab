Workspace layout

~/fosslab/
  fosslab.lib                 library definitions
  libs/<library>/<cell>/      one folder per cell, one file per view
      <cell>.sch .sym .gds .va .v .spice .md
      <cell>_2pole.va ...         more views of the same kind (Copy view...)
      <tb>.simenv.json            a testbench's Simulation Environment setup
      <tb>.<name>.simenv.json     its other, named setups
  sim/<library>/<cell>/       simulations: netlist, .raw waveforms, logs
      corners/ montecarlo/     Simulation Environment runs: one folder per run,
                               results.csv, histograms, bar charts
      montecarlo.<name>/ ...    the same, for a named setup
  verif/<library>/<cell>/    drc/  lvs/  pex/  with their reports and status
                               va/  compiled Verilog-A models (.osdi)

fosslab.lib accepts DEFINE <library> <folder> and INCLUDE <another fosslab.lib> (for instance a library your teacher shares, which you see read only).

The Simulation Environment's setup file

Everything the Simulation Environment window shows is saved in <testbench>.simenv.json next to the testbench's schematic. You never need to edit it by hand, but it is plain text, and it is sometimes quicker (e.g. to copy a corner table from one testbench to another):

{
  "variables": {"vdd": "1.2", "vcm": "0.8", "ibias": "10u", "cl": "1p"},
  "outputs": [
    {"name": "a0", "label": "DC gain", "min": 55, "max": null, "scale": 1.0, "unit": "dB", "expr": ""},
    {"name": "g1m", "label": "Gain at 1 MHz", "min": 20, "max": null, "scale": 1.0, "unit": "dB",
     "expr": "meas ac g1m find vdb(out) at=1e6"}
  ],
  "corners": [
    {"name": "ss_125C", "enabled": true, "mos": "mos_ss", "cap": "cap_wcs", "res": "res_typ",
     "temp": 125, "vars": {"vdd": "1.08"}}
  ],
  "montecarlo": {"runs": 200, "variation": "mismatch", "seed": 1, "jobs": 8},
  "wave": "vdb(out)", "wave_logx": true,
  "views": {"opamp_tut/opamp": {"view": "veriloga",
            "params": {"A0dB": "agauss(A0dB_mean, A0dB_sd, 1)"}}}
}

What a run does with it: the testbench is netlisted once; for each corner or Monte Carlo sample FOSSLab copies the netlist and changes the IHP .lib sections (mos_tt → the corner's, or → mos_tt_mismatch/mos_tt_stat for Monte Carlo), every .param of a variable, the temperature and the random seed; adds the outputs' expressions and the waveform at the end of the control block; runs ngspice; and collects every name = value ngspice prints. With views, the netlist of each listed cell is first replaced by the chosen view (a wrapper subcircuit with the same pins, connected by name): the extracted netlist, or the compiled Verilog-A model loaded with pre_osdi, its parameters set from the expressions.
