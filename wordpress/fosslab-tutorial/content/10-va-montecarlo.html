A Monte Carlo run of the transistor-level op-amp simulates 9 devices plus, after layout, hundreds of parasitic capacitors. In a system with ten op-amps (a filter, a ΔΣ modulator) and long transients that becomes very slow. The usual way out: characterise the op-amp once with transistor-level Monte Carlo, then give its Verilog-A model parameters with the same statistical distribution, and run the system-level Monte Carlo with the model. This chapter does it for the op-amp itself, so we can check that the model reproduces the transistor-level statistics.

What you need

  • The model opamp_va, compiled, and its testbench tb_opamp_va (chapter 4).
  • The transistor-level Monte Carlo of tb_opamp_ac, mismatch, 200 runs (chapter 9).

1. How the model gets random parameters

The testbench tb_opamp_va already prepares it. Each model parameter is drawn from a Gaussian whose mean and standard deviation are design variables:

.param A0dB_mean=57.6 A0dB_sd=0
.param A0dB_mc=agauss(A0dB_mean, A0dB_sd, 1)
...
.model opamp_va_model opamp_va A0dB={A0dB_mc} GBW={GBW_mc} VOS={VOS_mc} SR=10.6e6

agauss(mean, sd, 1) draws a new value every time ngspice reads the netlist, with the random seed of the run. The Simulation Environment gives every Monte Carlo run its own seed, so every run gets a different op-amp, exactly as with the transistors. With the _sd variables at 0 (as in chapter 4) every run is the nominal op-amp.

2. Take the statistics from the transistor-level Monte Carlo

Open the Simulation Environment of tb_opamp_ac, tab Results (after the Monte Carlo of chapter 9), and read the mean and σ of three outputs. Convert them to the model's parameters and units:

Transistor-level outputMeanσModel variable_mean_sd
DC gain57.61 dB0.031 dBA0dB57.610.031
Unity-gain frequency16.17 MHz0.228 MHzGBW (Hz)1.617e72.28e5
Output offset1.72 mV2.14 mVVOS (V)1.98e-32.14e-3

For a one-pole op-amp the unity-gain frequency is the gain-bandwidth product, so GBW takes the UGF statistics. VOS is input-referred: add the follower's gain error (VCM − VDD/2)/A0 = 0.2 V / 759 = 0.26 mV to the mean (chapter 4); the σ stays.

This is a simplification worth saying: the three parameters are drawn independently, as if they were uncorrelated. For mismatch that is a good approximation (the offset depends on the differences between twin devices, the gain and bandwidth on their sums). For process variation it is not: when the NMOS are fast, gain and bandwidth move together.

3. Enter them in the Simulation Environment

  1. Select tb_opamp_va and press Sim. Environment.
  2. Tab Design variables: double-click each of the six _mean and _sd variables and type the values of the table. (vdd, vcm, ibias, cl stay.)
  3. Tab Monte Carlo: Number of runs 200, Starting run 1. The analysis variation only changes IHP's transistor models, and this testbench has no transistors: leave it as it is.
  4. Run Monte Carlo.

Gain, bandwidth and offset are reproduced: the differences (0.14 mV in the mean offset, 5 % in its σ) are what two independent sets of 200 samples give (the uncertainty of a mean is σ/√N = 2.14/√200 = 0.15 mV). The model's Monte Carlo is as good as the transistors' for everything the model contains.

The phase margin is not reproduced at all: 89.5° in every run, while the transistors give 60.4° ± 0.3°. The model has no second pole, so it would say that any feedback circuit built with this op-amp is perfectly stable and never rings. That is the next step: your exercise.
